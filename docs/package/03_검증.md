# 03 검증

## 1. 문서 정보와 실행 지시

프로젝트: 생각바로 · 문서 버전: 1.0 · 작성일: 2026-10-28 · 기준 시간대: Asia/Seoul · 설계 기준: 01 v1.0

관련 문서: [앱 설계](01_앱설계.md), [개발 지시](02_개발지시.md).

Claude 실행 지시: 프로젝트 실행 환경과 두 관련 문서를 읽고 아래 TC를 실제 실행하라. 이 문서를 만든 시점에는 목표 앱을 실행하지 않았으므로 **전체 결과는 미실행**이다. 테스트 방법을 작성했다는 사실을 통과 근거로 사용하지 말라.

## 2. 대상·환경·사전 조건

- 대상: 01의 REQ-001~016을 구현한 생각바로 실사용 앱. 현재 정적 디자인의 일부 브라우저 검사 결과는 목표 앱 전체 검증과 별개이다.
- 테스트 전 코드 commit 또는 배포 버전·브라우저 버전·운영체제·화면 크기·실제 기기 여부를 기록한다. 현재 아직 목표 구현 버전이 없어 이 정보는 실행 시 기록한다.
- 데이터: 테스트용 노트·원음만 사용한다. 실제 사용자 기록이 있는 저장소를 초기화하거나 덮어쓰지 않는다.
- 역할: 1차는 현재 브라우저의 1인 사용자. 관리자·팀 공유 권한 시험은 범위 밖이다.
- AI 실서비스 시험: 서버 환경변수와 실제 사용 가능한 계정 필요. 키가 없으면 해당 TC는 차단. 모의 AI는 저장·오류 단위 테스트용이며 실서비스 TC 통과 근거가 아니다.
- 마이크 시험: 실제 장치의 녹음 권한 필요. 녹음 불가 환경이면 장치 관련 검증을 차단 또는 미실행으로 분리한다.
- 실행 명령: 실제 프로젝트의 package.json과 README를 확인한다. 02에 적은 npm 스크립트는 제안이며 존재를 확인한 뒤 사용한다.
- 근거 요약: 사용자 최신 확정과 reference-web의 실제 코드 확인을 반영했다. 기존 프로젝트 지침 파일과 AI 계정은 미제공이다. 상세 근거는 01의 문맥 표를 따른다.

100,000자 입력 생성 예시: 한글·이모지·개행을 포함하는 패턴을 반복하고 Python 코드포인트 기준으로 정확히 100,000자만 테스트 fixture로 만든다. 이 테스트 fixture의 길이 설정을 앱 제품 코드의 제한으로 옮기지 않는다. 비교는 동일한 Unicode·줄바꿈 인코딩으로 정규화 기준을 먼저 정한 뒤 SHA-256 또는 전체 문자열 동등성으로 확인한다. 저장 중 임의의 공백·개행 정규화를 하지 않는다.

실제 AI 품질은 글 길이만으로 판정하지 않는다. 원문에 있는 고유명사·시간·숫자·단위·부정·조건·사건·관계 목록을 미리 작성하고 결과와 대조한다. 단순메모는 항목 누락과 허구 추가 0건을 요구한다. 아이디어·스토리는 확장 부분을 원문 사실로 오인시키지 않는지 함께 확인한다.

## 5. 화면·데이터·권한·회귀 검증

- 화면: TC-001·016·027. 홈·편집·녹음·상세·설정에서 실제 화면 넘침과 입력 키보드를 확인한다. 430px iframe 미리보기만 확인하고 실제 iOS 마이크·키보드를 검증했다고 보고하지 않는다.
- 데이터: TC-009·010·012·015·021·022·026. 원문·생성본·수정본·원음·버전을 별도로 대조한다. JSON에는 녹음이 포함되지 않는다는 안내와 실제 산출물이 일치해야 한다.
- 권한: TC-014·017·024·025. 마이크 거부·AI 미설정·비밀키 노출·콘텐츠 실행 여부를 확인한다. 다중 계정 데이터 격리는 1차 범위가 아니며 클라우드 인증이 구현된 것으로 보고하지 않는다.
- 기존 기능 회귀: 브랜드 변경 후 이전 이름·아이콘 깨짐 여부, 종류 변경 시 데이터 보존, 검색·즐겨찾기·정렬·목록 전환, 이전 디자인 데이터 읽기·변환을 확인한다.
- 해당 없음: 세금·수량·공정률 등 계산, 결제·메일 발송, 영구 삭제, 팀 공유·역할별 권한. 이 기능의 테스트를 임의로 추가하지 않는다.
- API 키·실제 원음·개인정보가 포함된 개발 도구 화면은 증거에서 가린다. 정적 샘플과 실제 API 응답은 결과에 구분한다.

## 7. 최종 판정과 인수 조건

현재 판정: **목표 앱 검증 미실행**. 본 문서 생성·REQ 연결 검토와 앱 실행 검증은 다르다.

최종 인수 시 필수 REQ의 정상·경계·실패 검증과 핵심 회귀 시험이 통과해야 한다. 원문 손실·녹음 손실·무단 덮어쓰기·비밀키 노출·요약으로 대체·글자 수 임의 제한은 주요 결함으로 남긴다. AI 키가 없어 실제 전사·제목·상세 생성을 시험하지 못했다면 “기본 기능 확인, AI 통합 차단”으로 보고하며 전체 완료로 계산하지 않는다.

검증 완료와 배포 완료는 별개이다. 배포했다면 실제 대상 환경·접근 범위·API 서버 연결·HTTPS·남은 제한을 별도로 보고한다.
