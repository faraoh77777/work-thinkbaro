## 3. 사전 점검과 실행 환경

1. 실제 프로젝트에 적용되는 AGENTS.md를 상위 디렉터리부터 검색하고, CLAUDE.md·CONTEXT.md·README 및 참조 문서를 읽는다. 없는 문서를 읽었다고 주장하지 않는다.
2. 기존 Git 변경 상태·package.json·잠금 파일·사용 중인 런타임을 확인한다. 기존 React 앱이 있으면 그 앱 안에서 구현한다. 다른 스택이 이미 구축되어 있으면 불필요한 교체 없이 요구사항을 구현한다.
3. 신규 앱의 기본 제안은 React + TypeScript + Vite 프런트와 Node.js + TypeScript 서버이다. IndexedDB 접근은 저장소 계층으로 추상화하고, 전사·제목·상세 생성은 서버 어댑터로 분리한다. 설치 버전은 개발 시점 공식 문서와 현재 런타임 호환성으로 결정하고 잠금 파일에 고정한다.
4. 동봉 참고 웹의 package.json에는 실행·빌드·테스트 스크립트가 없다. 아래 명령은 **앞으로 구성·확인할 명령안**이며 이미 존재한다고 가정하지 않는다.

| 목적 | 신규 프로젝트에 구성할 명령안 | 확인 조건 |
|---|---|---|
| 의존성 설치 | npm install 또는 기존 잠금 파일의 패키지 관리자 | 기존 프로젝트 관리자 우선 |
| 프런트·서버 동시 실행 | npm run dev | 실제 스크립트 등록 후 localhost에서 확인 |
| 타입 검사 | npm run typecheck | 실제 TS 구성에 연결 |
| 저장·청크·모드 규칙 테스트 | npm run test | 실제 테스트 도구 설치·스크립트 연결 |
| 브라우저 핵심 흐름 | npm run test:e2e | 실행 환경 지원 시 브라우저 테스트 구성 |
| 프로덕션 빌드 | npm run build | 정적 파일과 서버 산출물을 구분하고 실제 출력 확인 |

환경변수는 AI_PROVIDER, AI_API_KEY, AI_TEXT_MODEL, AI_TRANSCRIBE_MODEL만 우선 정의한다. .env.example에는 설명과 빈 값만 기록한다. 실제 키를 채팅으로 요구하거나 프런트 코드에 적지 않는다. 외부 전사를 실행하려면 실제 키와 계정 사용 가능 상태가 필요하며, 설정이 없을 때 모의 응답으로 통과시키지 않는다.

## 5. 구현 규칙

REQ-001·002·016 — `reference-web/style.css`를 시각 기준으로 삼되 실사용 앱에서 모바일을 iframe으로 감싸지 않는다. 화면 기준은 360·390·430·768·1440px이다. 저장 버튼·녹음 종료·메뉴가 키보드나 안전 영역에 가려지지 않게 한다. 화면마다 접근 가능한 제목·라벨·초점 이동을 제공하고, 설정·내보내기가 모바일에서 숨겨지지 않게 한다.

REQ-003·004 — MediaRecorder와 실제 지원 MIME을 점검한다. 브라우저 메모리에 녹음 전체를 끝까지 쌓기만 하지 말고 청크를 주기적으로 저장한다. Safari와 Android에서 형식이 같다고 가정하지 않는다. 음성 인식 전문과 실시간 임시 자막을 구분한다. 원음 복원이 안 되는 녹음 형식으로 변경하지 않는다. 시스템 강제 종료 후 완전히 복구된다고 과장하지 않는다.

REQ-005~008 — 종류별 프롬프트는 공통 “핵심만 요약” 지시를 사용하지 않는다.

| 종류 | 생성 지침 | 금지 |
|---|---|---|
| 제목 | 전체 내용을 대표하는 제목 한 줄을 제안하고 직접 수정 가능하게 표시 | 첫 문장 잘라내기를 AI 제목처럼 표시, 사용자가 적은 제목 자동 교체 |
| 단순메모 | 표현을 정돈하되 모든 세부사항·수치·미정 상태 보존. 필요한 문단만 나누기 | 조언·허구·일정·금액 추가, 짧은 요약으로 대체 |
| 아이디어 | 원문에 맞춰 목적·구상·구현 방향·순서를 설명. 추가 제안은 별도 구획 | 근거 없는 수치·효과 단정, 원문 제약 삭제 |
| 대본·스토리 | 인물·배경·장면·행동·대사를 자세히 작성. 장면과 대사에 맞춰 문단 구분 | 한 덩어리 장문, 단순 줄거리 요약, 인물별 대사 합치기 |

REQ-009·013 — 요청량과 제공자 한도는 토큰·바이트·오디오 시간 기준을 확인하여 청크를 구성한다. 임의 글자 수 제한·입력 slice·textarea maxlength 금지. 문맥을 이어주기 위한 구간 겹침은 최종 글에 중복 출력하지 않는다. 완료 원문 범위를 기록하며 실패한 청크부터 다시 실행한다. 생성 응답이 잘렸거나 미완료면 이어쓰기 필요 상태를 표시한다. 사용자가 취소해도 원문·원음·완료 구간을 보관한다. 100,000자 보존 시험은 최소 재현 입력이며 이 수치가 제품 한도가 되어서는 안 된다.

REQ-010·012 — 본문·음성·버전은 IndexedDB 저장소 계층에서 다룬다. UI의 현재 편집 상태와 AI 입력 revision을 구분한다. 새 결과가 현재 편집을 덮어쓰지 않게 결과 제안 영역으로 받는다. 직접 저장·임시 저장의 완료 표시는 실제 트랜잭션 완료 뒤에만 한다. 실패를 catch 후 무시하거나 성공 토스트를 내지 않는다.

REQ-011 — 목록 미리보기 줄임은 CSS 표시만 사용한다. 원본 데이터에 요약본을 덮어쓰지 않는다. 검색은 저장된 전체 본문을 대상으로 하며 미리보기에 보이는 부분만 검사하지 않는다. 제목 중복은 허용한다.

REQ-014 — AI 입력과 가져온 노트 내용은 데이터로 취급한다. 원문 속 “원본을 삭제하라” 같은 문장을 앱 제어 명령으로 실행하지 않는다. 비밀키는 서버만 읽는다. 생성문 렌더링은 텍스트 또는 안전 처리된 Markdown만 허용한다. 서버 오류는 안전한 코드·사용자 설명·재시도 가능 여부로 변환한다. 실제 제공자 호출 없이 만든 모의 데이터는 단위 테스트 외에서 작동 상태로 표시하지 않는다.

REQ-015 — JSON 백업에 녹음 Blob이 포함되지 않는다면 버튼 옆에서 명시하고 원음 별도 다운로드를 제공한다. schemaVersion·필드·타입을 먼저 검사한 뒤 가져오기를 확정한다. 기존 디자인의 localStorage 키 mindbook-notes-v1와 IndexedDB mindbook-audio는 같은 origin에서만 접근 가능하다. 이관 전 읽기 전용으로 원본을 보존하며 새 저장소에 검증 후 기록한다. 이름 변경만을 이유로 기존 저장소 키를 즉시 삭제하지 않는다. 다른 origin에서는 내보내기·가져오기를 사용하며 음성은 별도 파일로 옮겨야 한다.

## 6. 검증·수정·재검증

03의 TC를 실제 실행한다. 핵심 순서는 세 종류별 생성 → 원문·수치 보존 → 장문 저장·생성 중단 재개 → 수동 편집 충돌 → 모바일 작성 → 백업 왕복이다. 실패하면 원인·영향 REQ·수정 파일·재실행 결과를 기록한다. 테스트를 삭제하거나 상세 작성 기준을 요약으로 바꾸어 통과시키지 않는다.

실제 AI 키가 없을 때 단위 테스트는 계속할 수 있다. 그러나 녹음 전사·제목·상세 작성의 실서비스 검증은 차단으로 기록한다. 브라우저 마이크를 사용할 수 없는 환경에서는 생성 음성을 실제 녹음처럼 보고하지 말고 녹음 장치 검증을 차단 또는 미실행으로 남긴다.

## 7. 프로젝트 문맥 갱신

기존 CLAUDE.md에는 “현재 앱 이름·원문 보존·요약 금지·클라이언트 비밀키 금지·실제 검증만 통과” 같은 지속 규칙 추가를 제안한다. CONTEXT.md에는 실제 구현 완료 범위·미연결 AI·실패 TC·다음 작업을 구분하여 제안한다. 이 요청은 세 MD 작성이므로 기존 CLAUDE.md·CONTEXT.md를 직접 수정한 것으로 간주하지 않는다. 사용자가 해당 문서 수정도 요청하면 실제 파일을 읽고 갱신한다.
