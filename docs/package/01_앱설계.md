## 3. 목적·사용자·개발 범위

목적은 떠오른 생각을 음성 또는 글로 즉시 붙잡고, 목적에 따라 충분히 자세한 문서로 정리하여 보관하는 것이다. 기본 사용자는 자신의 기록을 작성하는 1인 사용자이다. 1차에는 사용자 계정·관리자 역할·팀 공유 권한이 없다.

포함: 세 종류의 기록, 원음 녹음·재생, 전문 전사, 제목 제안, 종류별 상세 작성, 긴 글 분할 처리, 원문과 버전 보존, 브라우저 지속 저장, 검색·필터·즐겨찾기, JSON 백업·복원과 원음 다운로드, 모바일·PC 반응형.

후속: 회원가입, 클라우드 동기화, 협업, 유료 구독, 외부 SNS 공유, 알림, 대량 파일 전사, 타오 전용 제작 기능, 앱스토어 배포. 이번 구현 지시에 자동 포함하지 않는다. 금액·세금·공정률 계산은 해당 없음.

## 5. 사용 흐름·메뉴·화면 구성

흐름: 홈 → 작성 종류 선택 → 직접 입력 또는 녹음 → 원음 보관·전문 전사 → 원문 확인·보정 → 제목과 상세 글 생성 → 생성 결과 검토·수정 → 저장 → 종류별 조회·재생·수정·백업.

직접 글을 쓰는 경우 녹음·전사를 거치지 않는다. 사용자가 자세히 작성을 실행하면 본문과 함께 제목도 자동 제안한다. 제목만 다시 만드는 버튼도 제공하며 수동 제목은 유지한다. 녹음 원음은 전사 실패와 관계없이 저장할 수 있다. AI가 미연결이어도 직접 작성·수동 제목·저장은 사용할 수 있다.

- 로고 텍스트는 생각바로, 설명은 “떠오른 생각, 바로 글로.”. 모바일 상단에서 앱명과 메뉴 버튼이 줄바꿈 충돌하지 않게 한다.
- 디자인 참고 웹의 배치와 분위기를 따른다. 작은 보조 글씨는 그대로 복사하지 말고 가독성에 맞게 키운다. 본문·입력은 모바일 16px 이상, 보조 문구는 12px 이상을 원칙으로 한다.
- 동봉 `mobile.html`은 작은 화면을 보여주기 위한 iframe 미리보기다. 실사용 앱은 iframe 안에 가두지 말고 실제 반응형 화면으로 만든다.
- 카드에서만 2~3줄 미리보기를 사용한다. 이것은 저장된 본문 요약이나 내용 삭제를 뜻하지 않는다.

업무 규칙:

1. 단순메모는 정리이지 창작이 아니다. 예: “금요일 3시, 도면 2장, 비용 아직 모름”의 시간·수량·미정 상태를 보존한다. “비용 10만원” 같은 추정치를 추가하지 않는다.
2. 아이디어는 원문에 기초한 설명과 확장 제안을 분리한다. 내용에 해당하지 않는 억지 목차로 길이를 늘리지 않는다.
3. 스토리는 원문 의도를 유지한 창작 확장을 허용한다. 배경 → 등장인물 → 장면별 이야기 순서로 작성하되 짧은 원문에 맞게 조절한다. 장면 제목 다음에 빈 줄, 행동 설명은 문단, 대사는 “인물명: 대사”로 인물별 줄 구분. 본문은 읽을 수 있는 일반 텍스트 또는 안전한 Markdown으로 보관한다.
4. 생성 결과를 몇 자·몇 문장으로 요약하라는 시스템 지시는 사용하지 않는다. 제공자 출력 한도 때문에 잘린 응답은 완료가 아니라 이어쓰기 필요 상태이다.
5. 긴 입력은 원문 구간·명칭·수치·핵심 사건을 추적하는 인덱스를 두고 순차 처리한다. 중간 단계도 상세 정보가 사라지는 단순 요약으로 대체하지 않는다. 각 결과가 어느 원문 구간을 반영했는지 유지한다.
6. 글자 수는 Unicode 코드포인트 기준 안내 수치일 뿐 저장 한도가 아니다. 바이트·토큰·시간·청크 수는 각각 별도 단위를 사용한다.
7. 녹음 상태: idle → requesting → recording ↔ paused → stopping → saved. 실패 시 이미 받은 청크를 보존하고 failed 또는 interrupted로 표시한다. 녹음 길이의 임의 고정 제한을 두지 않되 브라우저 백그라운드 중단과 기기 용량은 실제 제약으로 안내한다.
8. AI 상태: queued → running → completed 또는 incomplete/failed/cancelled. 재개는 완료된 청크를 재사용하며 네트워크 재시도로 완료 글을 중복 추가하지 않는다.
9. 다른 탭 또는 늦게 도착한 생성 결과는 revision 비교 후 별도 버전으로 보관한다. 수정 중 내용을 조용히 덮어쓰지 않는다.
10. 동일한 제목은 허용한다. ID는 고유하다. 백업 복원 시 ID가 겹치면 기존 노트를 유지하고 새로운 ID의 복사본을 만든다. 1차에는 영구 삭제·자동 정리 기능을 추가하지 않는다.

## 7. 저장·연동·비기능 조건

브라우저 저장: 긴 본문과 음성을 모두 IndexedDB에 보관한다. 큰 음성을 base64로 localStorage에 넣지 않는다. 직접 저장은 트랜잭션 완료 뒤에만 완료 표시한다. 편집 임시 저장은 짧은 지연 후 실행하되 미완료 상태를 표시한다. 사용자의 저장 용량 부족·사생활 모드·저장 차단은 재현 가능한 오류로 처리한다. 브라우저를 강제 종료하면 아직 디스크에 기록되지 않은 구간은 복구 보장하지 않는다.

AI 연동은 다음 **새로 구현할 내부 API 계약안**이다. 현재 제공되는 엔드포인트가 아니다.

| 작업 | 내부 계약안 | 주요 입력 | 출력·실패 |
|---|---|---|---|
| 전문 전사 | POST /api/transcribe | 실제 MIME의 오디오 구간, jobId·chunkIndex·locale ko-KR | 전문 텍스트·구간 순서·완료 여부, 서비스 오류 코드 |
| 제목 | POST /api/title | sourceText 또는 긴 글의 전체 구간 인덱스, noteType·inputRevision | 제안 제목·inputRevision. 제목만 한 줄로 생성 |
| 상세 작성 | POST /api/compose | noteType·sourceText 구간·sourceRange·이전 문맥·inputRevision | 상세 문단·coveredRanges·continuation 상태. 결과 잘림을 명시 |

AI 제공자별 요청 파라미터는 개발 시 공식 문서로 확인한다. 본 문서의 필드명을 외부 업체 API가 그대로 제공한다고 가정하지 않는다. 어댑터가 내부 계약과 실제 업체 형식을 변환한다. 환경변수 이름은 AI_PROVIDER, AI_API_KEY, AI_TEXT_MODEL, AI_TRANSCRIBE_MODEL이다. 실제 키 값은 문서·소스·로그·클라이언트에 넣지 않는다. 프런트 전용 환경변수로 비밀키를 전달하지 않는다.

원음·본문이 외부 AI로 전송되는 시점은 사용자가 글로 변환 또는 자세히 작성·제목 생성 기능을 실행했을 때이다. 자동 전송을 숨기지 않는다. 민감한 본문과 원음을 서버 로그에 남기지 않는다. 생성문·가져온 파일을 실행 가능한 HTML로 삽입하지 않는다.

배포는 HTTPS가 필요하다. 정적 프런트만 배포하면 실제 AI를 호출할 서버가 없다는 점을 명확히 하라. localhost용 서버를 공개 호스트로 옮길 때는 허용된 사용자·요청 제한·API 비용 보호가 결정되기 전 유료 AI 엔드포인트를 익명으로 열지 않는다.

지원 환경은 개발 시점 안정 버전의 Android Chrome·iOS Safari·데스크톱 Chrome/Edge를 우선 검증한다. 각 브라우저에서 실제 MIME 지원을 감지한다. 브라우저 SpeechRecognition을 유일한 전사 경로로 삼지 않는다. 라이브 전사를 보조 기능으로 쓸 수 있으나 최종 전문 전사와 원음 보관 기준은 유지한다.
